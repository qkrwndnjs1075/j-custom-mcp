# 연동 확인 문의 초안

상태: 미발송. 외부 발송은 사용자 승인 후 진행합니다.

## 티머니GO

받는 사람: tmoneygo@tmoney.co.kr

제목: 버스 좌석 확보 후 사용자 Npay 인증을 이어가는 외부 연동 문의

안녕하세요. 사용자가 지정한 고속·시외버스의 취소표를 감시하고, 빈 좌석이
발견되면 예매를 돕는 MCP 서버를 개발하고 있습니다. 결제는 사용자가
GO/Npay의 인증 화면에서 직접 인증하는 흐름을 원하며, 자동결제로 이를
대체하거나 카드번호·결제 비밀번호를 AI에 전달하지 않으려 합니다.

외부 서버에서 확보한 좌석을 유지하면서 사용자가 GO/Npay 결제 인증을
완료하고 발권까지 이어갈 수 있는 지원 방식이 있는지 문의드립니다.

1. 기존 좌석 점유를 이어받는 결제 URL 또는 앱 연결 방식과, 외부 서버가
   인증 완료·실패·만료를 확인할 콜백 또는 조회 API를 제공하시나요?
2. 지원한다면 개발 문서·테스트 환경·이용 신청 절차와 좌석 점유 만료 및
   발권 결과 확인 방법을 안내받을 수 있을까요?
3. 취소표 감시를 위한 잔여 좌석 조회의 허용 주기나 호출량 제한도
   함께 확인하고 싶습니다.

현재 실제 결제·발권까지 검증한 상태는 아닙니다. 담당 부서가 따로 있다면
연결 부탁드립니다. 감사합니다.

수신처 근거: [티머니GO 공식 페이지의 제휴문의](https://www.tmoneymobility.co.kr/terms/)
(2026-10-25 확인).

## VOOY

받는 사람: help@vooy.com

제목: 사용자 지정 MCP의 백그라운드 완료 알림과 외부 인증 연결 문의

안녕하세요. 본선에서 사용할 사용자 지정 MCP를 준비하고 있습니다.
원격 MCP 서버가 버스 빈 좌석을 감시하다가 조건이 맞으면 사용자에게
알리고, 사용자가 외부 결제 서비스에서 직접 인증하는 흐름을 검토 중입니다.

1. 최초 도구 호출이 끝난 뒤 MCP 서버에서 발생한 결과를 VOOY에 전달하고,
   앱이 백그라운드에 있을 때 사용자에게 푸시로 알리는 지원 방식이 있나요?
   콜백·웹훅·작업 완료 통지 또는 권장 레시피 구성을 알고 싶습니다.
2. 외부 인증 페이지를 여는 MCP URL elicitation을 지원하나요? 지원한다면
   인증 완료 후 원래 작업을 이어가는 방법과 호출·대기 시간 제한을
   안내받을 수 있을까요?

계정 연결용 OAuth와 개별 결제 인증을 구분해 구현하려고 합니다.
관련 문서나 금전 거래 없이 확인할 수 있는 테스트 방법이 있다면
안내 부탁드립니다. 감사합니다.

수신처 근거: [VOOY 공식 홈페이지의 문의 연락처](https://vooy.com/ko)
(2026-10-25 확인).
